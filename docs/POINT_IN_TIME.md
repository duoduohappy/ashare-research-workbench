# 历史时点与严格成交研究

在「数据质量与来源」或「策略实验室」进入「历史时点与严格成交研究」。这一流程把历史存续股票池、退市处置、财报版本可用时点与整数股账户放在一起检验，独立于共享行情和原有固定候选池实验。当前支持动量与 ROE 两种排序，不会自动替换或启用运营策略。

## 使用流程

1. 点击「载入合成历史样本」，即可查看上市、退市、ST、停牌与财报版本覆盖。演示包含 6 只虚构证券、160 个工作日、一次财报更正和一项退市现金处置情景。工作日日历不是交易所日历，证券代码不表示对相同代码真实公司的判断。
2. 选择本面板自己的截止日期，核验历史池与财报；该日期不受上方共享回放控制。
3. 选择动量或 ROE 排序，设置回看窗口、调仓间隔、持股数量、资金、滑点及开盘集合竞价参与率，再运行研究。
4. 查看历史池、财报覆盖、状态热力图、费用后净值、回撤、费用和委托分布七张图；展开查看每次信号池、财报版本、逐笔委托及退出处置。
5. 导出数据包及研究记录；使用相同数据包、参数和截止日复算，核对结果哈希。已保存的数据包可通过「刷新数据包列表 → 打开所选数据包」重新加载。

真实数据使用「导入并核验」。导入成功仅表示结构与内部一致性检查通过，不证明来源真实、样本完整或时间戳正确。没有默认的全市场 PIT 数据服务，也不会使用今天的股票名单补齐历史。请向具有相应历史覆盖的数据源取得数据，再映射为下述格式；不要求提供账户凭据。

## 数据包格式

JSON 顶层字段为 `schema, provenance, calendar, securities, daily, financials, settlements`，当前 `schema=1`。可从界面导出演示包查看完整、可运行的格式；仓库也提供 [合成示例](examples/pit-demo.json)。HTTP 导入建议小于 1.4 MB，目前一次支持 2–30 只股票、30–2500 个日历交易日，用于分批验证，不是全市场规模回测引擎。

| 字段 | 必填内容与口径 |
| --- | --- |
| `provenance` | `mode` 为 `imported` 或 `demo`；`source`、带时区的 `retrieved_at`、布尔值 `universe_complete`。完整性为来源声明，不是平台认证。 |
| `calendar` | 日期字符串数组，按时间递增、不可重复。真实研究需来自交易所日历，不能仅删除周末。必须覆盖研究窗口及预热窗口。 |
| `securities` | 每行 `code, listed_on, source`；退市样本还须同时提供 `last_trading_day, delisted_on`。上市日至最后交易日均属于历史池，不支持同一代码复用。名称不参与策略。 |
| `daily` | 每行 `code, date, is_st, suspended`。每只存续股票在每个日历交易日都须有一条记录，明确停牌时可以没有 OHLC。交易日额外需要 `close, raw_open, raw_close, raw_high, raw_low, volume_shares`，其中 `close` 是一致口径的复权收盘，原始 OHLC 不复权；所有成交量以股计，不是手。 |
| 开盘容量 | `daily.auction_volume_shares` 是开盘集合竞价的成交股数，须非负且不超过全天成交股数。缺失时订单被拒绝，不会用全天成交量替代。 |
| 涨跌停 | 建议提供 `reference_price` 和交易所逐日 `limit_up / limit_down`；无涨跌幅日明确提供 `no_price_limit:true`，且不同时提供上下限。特殊交易日使用 `special_session` 标记并提供明确价格边界或无涨跌幅标识。 |
| `financials` | 每行 `code, report_date, published_at, available_at, version, source, values`；ROE 排序读取 `values.roe`，各证券单位须一致。更正必须追加新版本，不能覆盖旧版。无报告可用时排除该证券的 ROE 信号，不拿当前报告回填。 |
| `settlements` | 可选，每只退出证券最多一条 `code, date, cash_per_share, kind, source`；`kind` 为 `actual` 或 `scenario`。情景处置不是实际回收证明。持仓退出后缺少处置，或处置尚未发生但缺少期间估值，研究会被阻断。 |

财报与行情的来源字段属于数据，不会执行其中的任何指令。数据包拒绝重复状态行、缺少明确状态的日线、报告可用时间早于披露时间、非有限数、价格与数量单位不明等问题。

## 历史池与退市处理

选股只使用信号日已经上市、且未超过最后交易日的证券。保留已退市证券的历史行情；不要求所有股票拥有共同日期交集，因此较晚上市和已退出股票不会因为整段样本不重叠而被整体删除。每次排序均导出当时历史池、排除原因与入选股票。

未来退市日不用于提前强制卖出。只有到实际退出时间后才进行显式终值处理；不会在退市前以事后知道的“最后一天”自动平仓。对已持有但退出上市交易范围的证券，要求明确退出现金记录或明确的情景处置，否则拒绝输出看似完整的净值。尚未发生处置时，当前版本没有独立的期间估值账本，因此阻断研究。

没有完整历史主表，仍然存在漏掉退市证券的可能。这里解决的是存储、选择与核对逻辑，不保证导入来源已经包含全部退市样本。

## 财报可用时点与版本

财报必须同时满足披露时间、可用时间都不晚于信号日 15:00。时间精确到时分时须带时区；只有日期的时间保守推迟到次日 00:00，因此公告当天不参与信号。`available_at` 表示该版本真正可供研究使用的时点，不能用抓取今天的数据冒充过去已取得的数据。

先选择已可用的最新报告期，再选择该报告期已可用的最新版本。晚披露的更正不能回写更正前信号；过期报告期的更正也不会覆盖更新报告期。原始披露文件的真实性、版本完整性仍需来源核对。

历史行情当前只冻结导入版本，不提供逐日价格修订版本的双时态数据库；不能据此声称全链路恢复了当时行情。

## 成交与账户口径

- 前一交易日收盘生成排序，调仓日开盘执行；按目标持股数量等预算分配，资金不足或部分成交后不假定补足目标权重。余单当日撤销，不在之后自动追单。
- 使用原始价格与整数股，FIFO 区分可卖库存，实施 T+1；普通股买入按 100 股递增，科创板至少 200 股、之后 1 股递增，剩余零股卖出与部分成交单独处理。
- 按交易日匹配规则：创业板 2020-08-24 起调整为 20%；主板风险警示股 2026-07-06 起由 5% 调为 10%；注册制新股前五交易日、旧制 IPO 及特别交易日分别处理。建议优先导入交易所实际上下限，不靠股票当前简称推断历史 ST。
- 开盘封涨停不假定可以买入，封跌停不假定可以卖出；停牌、零成交量、开盘竞价容量、申报数量上限、资金与费用均可阻断或减少成交。
- 每侧默认佣金万三、最低 5 元；卖出印花税按 2023-08-28、过户费按 2022-04-29 切换。费用日历仅覆盖 2015-08-01 以后。佣金视为包含其他经手规费，未建立个人分红税账本。
- 对有持仓股票发现复权因子变化时阻断，包含跨停牌后的变化；不通过复权因子静默增加“等价股数”。当前不提供逐笔分红送转登记、税款与应收款账本。
- 日线滑点仍是情景模型，成交价受观察到的日价格范围约束；不模拟开盘集合竞价队列、分钟行情、盘中临停、订单撤改单、盘口冲击或真实券商撮合。开盘竞价成交量本身也只有竞价结束后才能确认，研究假定委托参与该竞价，不用于提前选择股票。

原有因子、组合、状态与策略模块不因此自动获得这些严格数据口径。新增流程提供独立的可验证路径，不把旧近似实验重新命名为严格研究。

## 保存、复算与备份

数据包以 SHA-256 内容标识保存在数据根目录的 `point_in_time/`，该目录忽略 Git；它是历史样本的本地输入存储，不纳入当前运营备份。请单独导出备份。

研究结果包含输入内容标识、全部账户路径、参数、规则版本、Python 版本、引擎源码指纹及完整结果哈希。复算失败或哈希不同会明确显示；服务启动后热修改引擎源文件也会要求重启。哈希是内容核对，不是数字签名或供应商真实性认证。导出研究记录后，仍须同时保留对应数据包。
